# Season Cast Survey Roles DDL Promotion

`20260716133000_admin_season_cast_survey_roles.sql` moves the skipped
TRR-APP backlog DDL into the backend migration chain without changing the live
table contract. It is expansion-only and remains unapplied.

## Preserved contract

- Identity remains `(trr_show_id, season_number, person_id)`; no `core.seasons`
  foreign key is added because survey roles can be authored before a core
  season row exists.
- Roles remain limited to `main` and `friend_of`; season numbers remain
  positive; UUID primary/default, timestamps, indexes, and updated-at trigger
  match the app backlog DDL.
- RLS remains enabled and API roles remain explicit default-deny. The optional
  `trr_app` role receives the same schema/table privileges when installed.
- No row backfill, rewrite, delete, rename, or table replacement is performed.

## Migration history boundary

This promotion uses the current migration sequence so it can enter an existing
environment without an out-of-order `--include-all` apply. Historical backend
migrations from April and June already assumed the app-created table/function;
therefore a backend-only replay from an empty database still requires a future
approved baseline/squash. Do not backdate this migration or rewrite the checksums
of already-applied migrations to repair that history.

## Gate 4B apply proof

Before preview or live apply, capture and approve all of the following:

1. Pending migration set and SHA-256 for the migration and rollback files.
2. Read-only `information_schema.columns`, `pg_constraint`, `pg_indexes`,
   `pg_trigger`, `pg_class.relrowsecurity`, `pg_policy`, and table-privilege
   snapshots for `admin.season_cast_survey_roles`.
3. Row count plus counts of invalid season numbers, invalid roles, null required
   fields, and duplicate `(trr_show_id, season_number, person_id)` groups. Do
   not retrieve row values.
4. Preview apply under the migration's five-second lock timeout and sixty-second
   statement timeout, followed by the same metadata snapshots and repository/API
   contract tests.
5. Explicit named approval before live apply, followed by checksum, migration
   history, schema metadata, RLS/default-deny, privilege, trigger, and endpoint
   verification.

The bounded read-only catalog/data proof is executable with:

```bash
psql "$TRR_DB_DIRECT_URL" -v ON_ERROR_STOP=1 \
  -f docs/db/season-cast-survey-roles/20260716133000_verify.sql
```

Run it against the existing target before apply and again after preview/live
apply. Capture checksums without changing state:

```bash
shasum -a 256 \
  supabase/migrations/20260716133000_admin_season_cast_survey_roles.sql \
  docs/db/season-cast-survey-roles/20260716133000_rollback.sql \
  docs/db/season-cast-survey-roles/20260716133000_verify.sql
```

## Rollback

Normal release rollback reverts the application/backend deployment and leaves
the pre-existing table intact. The companion rollback SQL is destructive and is
only valid for a newly created, empty environment after evidence proves this
migration—not the historical app migration—created the table. It intentionally
retains the shared `admin` schema and `admin.set_updated_at()` helper.

Only after the four destructive-rollback conditions in the SQL header are
independently proven and approved may an operator run:

```bash
psql "$TRR_DB_DIRECT_URL" -v ON_ERROR_STOP=1 \
  -f docs/db/season-cast-survey-roles/20260716133000_rollback.sql
```

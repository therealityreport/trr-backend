   thumbnail, parent-comment image, owner avatar, reader avatar and reply-author
   avatar. Generate the maintained ten display variants per post using real
   Pillow/native variant code. Do not replace variant generation with a stub.

   owner, request-budget, identity-pressure, persistence and completion guards.

This is a small, already-assigned single-image ingestion workload. It does not
represent carousel/video posts, assignment inference, huge comments inventories,

## Asset identity and byte policy proposed for the representative arm

- Define a checked fixture manifest before execution. Every URL maps to its
  asset identity, image dimensions, content type and deterministic byte SHA256.
  Source byte generation uses only that identity, never current time, Python
  randomized hash, invocation ordinal, caller files or network state.
- Twelve distinct post image identities have twelve distinct valid PNG bodies.
  For each post, the thumbnail and sole media URL are the **same exact URL** and
  return the same bytes. This intentionally tests per-snapshot cover/media URL

- Twelve parent-comment image identities have twelve further distinct PNG
  bodies. Text-only replies have no image. The owner, reader and replier have
  three distinct avatar identities/bodies, reused consistently across all posts.
- Therefore there are 27 distinct original source-body hashes. No distinct URL
  identity shares bytes in this representative arm. Keep the already-completed
  all-identical pair as the separate cross-identity byte-reuse stress case.
- Keep all source images 120×80 RGB PNG with the same deterministic generation
  method; vary deterministic pixel/color content per identity. Record actual
  compressed byte sizes rather than assuming equal compressed sizes. Retain
  actual generated bytes/hashes in a sanitized fixture artifact.
- Expected unique physical hosted objects, if native outputs confirm the stated
  policy: 12×(one shared cover/media original + ten variants), 12 comment images,
  three avatars = **147** in each arm. This is a falsifiable expectation, not an
  instruction to deduplicate, rewrite URLs, hide extra objects or force equality.
- Record every fake storage operation (`head`, `get`, `put`, conditional-put
  result and object key), CDN request, browser warmup and source request. Existing
  v2 retains per-process trace/CDN calls and the physical object inventory but
